# v0.1 experimental communication proposal

Status: **experimental**. Protocol major version `0`, UTF-8 JSON Lines, and USB
serial are development proposals for a single tile. They do not finalize the
connector, electrical transport, multi-tile bus, or public protocol described
in [the communication protocol](../communication-protocol.md).

## Development framing

Each frame is one compact JSON object followed by `\n`, with a maximum of 512
bytes including the delimiter. Development serial settings are 115200 baud, 8
data bits, no parity, and one stop bit. A receiver discards an incomplete or
oversized frame through the next delimiter and records a protocol error.

Tile frames require:

| Field | Type and bound | Meaning |
| --- | --- | --- |
| `v` | integer, exactly `0` | Experimental major version |
| `type` | allow-listed string | Message type |
| `tile_id` | non-empty UTF-8 string, at most 64 bytes | Discovered hardware identity |
| `seq` | non-negative integer | Per-boot monotonically increasing sequence |
| `uptime_ms` | non-negative integer milliseconds | Tile monotonic time |

Unknown versions and message types are rejected. The hub rejects duplicate or
stale sequence numbers per discovered tile. Unknown optional fields are ignored
only after the required envelope is validated.

## Prototype messages

```json
{"v":0,"type":"tile.hello","tile_id":"tile-0123456789abcdef","seq":1,"uptime_ms":12,"firmware":"0.1.0-dev","hardware_revision":"prototype","capabilities":["pressure","ws2812b"],"provisioned":true,"pressure_unit":"adc_raw"}
{"v":0,"type":"tile.pressed","tile_id":"tile-0123456789abcdef","seq":2,"uptime_ms":1842,"pressure_raw":2310}
{"v":0,"type":"tile.released","tile_id":"tile-0123456789abcdef","seq":3,"uptime_ms":2210,"pressure_raw":1200}
```

The raw ADC value is diagnostic, not a stable physical unit. A press and release
are debounced, hysteretic edges from the Velostat/copper-tape sensor rather than
momentary-switch states.

Future hub commands must include an explicit destination and request identity,
be allow-listed, enforce bounded values, and acknowledge only after hardware
validation. They are intentionally omitted from the executable v0.1 prototype.

## Unresolved before version 1

- Production tile identity, provisioning, and boot identity.
- Multi-tile topology, arbitration, addressing, and hot-plug behavior.
- Binary versus textual framing and an integrity check.
- Acknowledgements, retries, timeouts, stale-command handling, and queue limits
  at the transport boundary.
- Authentication, firmware update, clock synchronization, and threat model.
- Compatibility and conformance fixtures shared by hub and firmware.
